# 엔트로피 vs 행위 ML — 머리맞댄 비교 (같은 트래픽)

- 엔트로피: ZenSOC 수식(slack_alert.py) 그대로, **전역** 윈도우 100, baseline−4.0σ 급락 시 탐지
- ML: e2e 고정모델(`ml/model`, 학습 199창, high<-0.00202), **IP별** 15분 창
- 배경: 정상 브라우징(여러 IP) 위에 공격을 얹은 하나의 전역 스트림

| 시나리오 | 엔트로피(전역) | 행위 ML(IP별) | 설명 |
|---|---|---|---|
| 정상(오탐확인) | ✅ 정상 (1/22창 급락, 최대 4.1σ, shannon_path) | ✅ 정상 (공격 없음) | 둘 다 조용해야 정상 |
| 대량 브루트포스 | ✅ 탐지 (272/52창 급락, 최대 41.5σ, shannon_path) | ✅ 탐지 (점수 -0.0573) | 한 IP 가 스트림 뒤덮음 → 엔트로피 급락 |
| 느린 BOLA | ⛔ 놓침 (0/24창 급락, 최대 2.0σ, shannon_path) | ✅ 탐지 (점수 -0.1188) | 공격 몇 건이 정상에 묻힘 → 전역 엔트로피 안 흔들림 / IP별 ML 은 분리 |
| 브라우저 블렌딩 | ⛔ 놓침 (0/26창 급락, 최대 2.7σ, shannon_path) | ⛔ 놓침 (점수 0.0758) | 정상처럼 보임 — 둘 다 어려움 |
| IP 분산 | ⛔ 놓침 (0/24창 급락, 최대 3.8σ, shannon_path) | ⛔ 놓침 (공격 IP 가 창당 5건 미만 — 판단 불가) | IP마다 몇 건 → ML 창 5건 미만, 엔트로피도 전역선 안 흔들림 |

## 읽는 법

- **대량 브루트포스**: 엔트로피가 잡고 ML(IP별 15분)은 오히려 묻힐 수 있다 → 엔트로피의 강점.
- **느린 BOLA / 블렌딩**: 전역 엔트로피는 정상 트래픽에 희석돼 못 본다. IP별 ML 이 잡는다 → ML 의 강점.
- **IP 분산**: 둘 다 약하다(엔트로피=전역선 안 흔들림, ML=창당 5건 미만). 남은 숙제 = 계정·세션 단위.
- → **두 탐지의 사각지대가 반대.** ZenSOC 에 행위 ML 층을 더하면 서로의 빈틈을 덮는다.

> 한계: 합성 트래픽(상태코드·분포가 단순)·오프라인 재생. 실데이터·부하는 별도. 상세 근거 `../../shadow_api_monitoring/e2e_story/eval/`.

## 부록 — "윈도우를 늘리면 느린 공격도 잡히나?" (window_sweep.py)

경로 Shannon 엔트로피, 전역 윈도우 100→300→600:

| 윈도우 | 정상(오탐) | 브루트포스 | 느린 BOLA |
|---|---|---|---|
| 100 | 4.1σ | 39.5σ ✅ | **2.0σ** ⛔ |
| 300 | 3.9σ | 35.3σ ✅ | **2.0σ** ⛔ |
| 600 | 3.9σ | 25.4σ ✅ | **2.0σ** ⛔ |

- 윈도우를 키우면 정상 오탐 노이즈는 조금 준다. 하지만 **느린 BOLA 는 그대로 미탐**이고 브루트포스는 오히려 약해진다.
- 조용한 공격자는 전체의 ~9%(창 안에선 더 작음) → 전역 집계에선 창을 키울수록 비중이 더 작아진다.
- **윈도우 크기 문제가 아니라 '집계 단위' 문제.** 조용한 한 IP 는 전역 집계로 못 분리 → IP별(ML)이 답. 과민 오탐은 ① 지속 하락 요구 ② 흔들리는 srcip 대신 안정적 경로 신호로 해결.
